# GeoIP (country and ASN)

**Languages:** **English** · [Русский](../ru/20-geoip.md) · [中文](../zh/20-geoip.md)

The GeoIP subsystem in AEGIS is responsible for two independent tasks: determining the client's country (ISO 3166-1 alpha-2) for country rules and the world map in the panel, and determining the autonomous system number (ASN) of the client IP for AS-bound reputation. Both databases are in the MaxMind `.mmdb` format, are read via the `maxminddb` crate, ship bundled (db-ip Lite, CC BY 4.0) and are loaded out of the box without mandatory configuration.

The sources this chapter is based on: [`src/geoip.rs`](../../src/geoip.rs), [`src/real_ip.rs`](../../src/real_ip.rs), [`install.sh`](../../install.sh) (the `ensure_geoip_db` function), as well as the usage points in [`src/proxy/pingora_http.rs`](../../src/proxy/pingora_http.rs), [`src/proxy/pingora_admin.rs`](../../src/proxy/pingora_admin.rs), [`src/config.rs`](../../src/config.rs), [`src/metrics/geo_shard.rs`](../../src/metrics/geo_shard.rs) and [`src/bin/aegis-pingora.rs`](../../src/bin/aegis-pingora.rs).

---

## 1. What exactly GeoIP does

| Function | Database | Where it is used | File |
|---|---|---|---|
| Client country (alpha-2) | Country DB (db-ip "IP to Country Lite") | country deny list, world map, request log enrichment | `geoip.rs`, `pingora_http.rs` |
| AS number (ASN) | ASN DB (db-ip "IP to ASN Lite") | AS-bound reputation (Tor/Spamhaus + operator), the `asn_reputation` ML feature | `geoip.rs`, `asn_reputation.rs` |

The key invariant (see the module docstring of `src/geoip.rs`): the database is **mmap-loaded once at startup**, lookups are allocation-free; a failed load **never aborts startup** — it logs a warning and substitutes a no-op (`NoopGeoIp`), so the proxy keeps serving traffic when the database is missing or out of date.

## 2. The `GeoIpLookup` trait and its implementations

A platform-neutral facade (`src/geoip.rs`):

```rust
pub trait GeoIpLookup: Send + Sync {
    fn country(&self, ip: IpAddr) -> Option<String>;   // alpha-2, UPPERCASE
    fn asn(&self, _ip: IpAddr) -> Option<u32> { None }  // default: None
}
```

| Implementation | `country()` | `asn()` | When it is returned from `load_with_asn` |
|---|---|---|---|
| `NoopGeoIp` | `None` | `None` (the trait default) | neither a country nor an ASN database (or neither opened) |
| `MaxMindGeoIp` | from the Country DB | from the ASN DB, if attached via `with_asn` | the country database is loaded (ASN optional) |
| `AsnOnlyGeoIp` | `None` | from the ASN DB | only an ASN path is set, no country database |

- `country()` extracts `rec.country.iso_code` and converts it to **upper case** (`to_ascii_uppercase`). `None` means: a private range, an unallocated block, or no database.
- `asn()` returns `rec.autonomous_system_number`. It is `None` by default, so implementations without ASN need not override anything.
- Country and ASN are **two separate `.mmdb` files** (that is how MaxMind/db-ip ship them), so the ASN reader is attached by a separate method, `MaxMindGeoIp::with_asn(path)`.

> Honest caveat: the record schemas are `geoip2::Country` / `geoip2::Asn` from the `maxminddb` crate itself (zero-copy with correct lifetimes); a hand-written struct did not pass the borrow checker.

## 3. Bundled databases (seeding)

AEGIS ships working databases in the repository under `data/geoip/`:

| Constant (in `geoip.rs`) | File name | Source | Licence |
|---|---|---|---|
| `BUNDLED_COUNTRY_DB_NAME` | `dbip-country-lite.mmdb` | db-ip "IP to Country Lite" | CC BY 4.0 |
| `BUNDLED_ASN_DB_NAME` | `dbip-asn-lite.mmdb` | db-ip "IP to ASN Lite" | CC BY 4.0 |

The attribution returned by the admin API: `IP geolocation by DB-IP (https://db-ip.com) — CC BY 4.0` (see `api_geoip_status`).

### Seeding at install time (`install.sh`, `ensure_geoip_db`)

The `ensure_geoip_db` function copies the bundled country database to a writable absolute path that the daemon resolves automatically:

```sh
# src = $AEGIS_SRC/data/geoip/dbip-country-lite.mmdb
# dst = $AEGIS_HOME/geoip  (= /var/lib/aegis/geoip)
cp -n "$src" "$dst/dbip-country-lite.mmdb"   # -n: do not clobber a database updated by the operator
chown -R "$AEGIS_USER:$AEGIS_USER" "$dst"
chmod 0755 "$dst"; chmod 0644 "$dst/dbip-country-lite.mmdb"
```

- `cp -n` (no-clobber) guarantees that seeding will not overwrite a database that has already been updated via the Update button in the panel.
- If the bundled file is absent, install.sh logs `WARN: bundled GeoIP db missing … — map will be empty until Update is run` and does not fail.

### Seeding the ASN database (`install.sh`, the `aegis-refresh-feeds` script)

The ASN database is seeded not by `ensure_geoip_db` but by the `aegis-refresh-feeds` script generated by install.sh (part of `ensure_reputation_feeds`), because AS-bound reputation is enabled by default. The script pulls db-ip ASN-lite monthly:

```sh
GEO_DIR=/var/lib/aegis/geoip
M=$(date -u +%Y-%m)
curl -fsS -m 120 "https://download.db-ip.com/free/dbip-asn-lite-$M.mmdb.gz" -o "$TMP/asn.mmdb.gz"
gunzip -f "$TMP/asn.mmdb.gz"
install -m 0644 -o "$OWNER" -g "$OWNER" "$TMP/asn.mmdb" "$GEO_DIR/dbip-asn-lite.mmdb"
```

The script is installed with the `aegis-refresh-feeds.timer` timer (`OnCalendar=daily`, `RandomizedDelaySec=1h`, `Persistent=true`). All downloads are best-effort: on a network failure the module stays inert (zero false positives) rather than failing the installation. The daemon **hot-reloads** changed files by mtime — no restart is required. More about reputation feeds in [12-reputation.md](12-reputation.md).

## 4. The path resolver (priority: config → env → bundled)

Both resolvers in `src/geoip.rs` follow the same scheme and return `None` only when nothing is configured **and** no bundled file is found (then it is `NoopGeoIp`).

### Country: `resolve_country_db_path(configured)`

1. An explicit `[geoip] db_path` from the configuration (if non-empty) wins.
2. The `AEGIS_GEOIP_PATH` environment variable (if non-empty).
3. `default_country_db_path()` — the first existing file from a list of directories.

### ASN: `resolve_asn_db_path(configured)`

1. An explicit `[geoip] asn_db_path`.
2. The `AEGIS_ASN_PATH` environment variable.
3. `default_asn_db_path()`.

> The symmetry matters: a configuration path via the DSL leaves `cfg.geoip = None`, so the env/bundled fallback is the only way AS-bound reputation and the world map work out of the box.

### The list of search directories (in priority order)

For **both** databases `default_*_db_path()` tries the same directories, appending the corresponding file name:

| Priority | Directory | Purpose |
|---|---|---|
| 1 | `/var/lib/aegis/geoip` | the daemon's standard writable path (install.sh and Update write here) |
| 2 | `/etc/aegis/geoip` | an alternative system location |
| 3 | `/usr/local/src/aegis/data/geoip` | the source tree when installing from source |
| 4 | `data/geoip` | a relative path (running from the repository for development) |

A file written by the Update endpoint into `/var/lib/aegis/geoip` always wins over the bundled one (it is first in the list).

### Load points

| Binary / path | Call |
|---|---|
| `aegis-pingora` (data plane) | `pingora_http.rs`: `resolve_country_db_path` + `resolve_asn_db_path` → `load_with_asn(...)` |
| `aegis` (hyper) | `server.rs`: `load_with_asn(cfg.geoip.db_path, cfg.geoip.asn_db_path)` |

> Honest caveat: the hyper path (`server.rs`) loads the databases **strictly from `cfg.geoip`** (without the env/bundled fallback) — if `[geoip]` is not set, `None` is passed. The full config→env→bundled resolver is applied in the pingora data plane (`pingora_http.rs`), which is the primary one.

## 5. The logic of `load_with_asn`

`load_with_asn(country_path, asn_path)` (`src/geoip.rs`) is the single assembly point for `Arc<dyn GeoIpLookup>`. Empty/`None`/absent paths are acceptable; degradation is logged. The decision tree:

| country | asn | Result | Log |
|---|---|---|---|
| present | present, opened | `MaxMindGeoIp` (country + ASN) | `info`: country + ASN databases loaded |
| present | present, did **not** open | `MaxMindGeoIp` (country only) | `warn`: ASN reputation will only match CIDR entries |
| present | absent | `MaxMindGeoIp` (country only) | `info`: country database loaded |
| absent | present, opened | `AsnOnlyGeoIp` | `info`: ASN-only database loaded |
| absent | absent (or the country db did not open) | `NoopGeoIp` | `warn`: geo deny list ignored |

`load(path)` is a thin wrapper around `load_with_asn(path, None)` for callers without ASN.

## 6. Country rules (the `[geoip]` deny list)

Configuration (`src/config.rs`, the `GeoIpConfig` struct):

| Field | Type | Default | Purpose |
|---|---|---|---|
| `db_path` | `String` | — (mandatory for the block) | path to the Country `.mmdb`; without it the whole block is a no-op |
| `asn_db_path` | `Option<String>` | `None` | path to the ASN `.mmdb`; without it only CIDR reputation entries match |
| `deny_countries` | `Vec<String>` | `[]` | alpha-2 codes to block (case-insensitive). An empty list = monitoring mode |
| `attack_mode_only` | `bool` | `false` | apply the deny list only while the anomaly detector sees the host as "under attack" |

Example:

```toml
[geoip]
db_path = "/var/lib/aegis/geoip/dbip-country-lite.mmdb"
asn_db_path = "/var/lib/aegis/geoip/dbip-asn-lite.mmdb"
deny_countries = ["RU", "KP"]
attack_mode_only = true   # a dormant geo block, activated only during a DDoS
```

### The deny check (`geoip_deny`, `src/proxy/pingora_http.rs`)

```rust
fn geoip_deny(&self, ip: IpAddr, host: &str) -> Option<String> {
    let cfg = self.geoip_cfg.as_ref()?;                       // no [geoip] → skip
    if cfg.attack_mode_only && !self.anomaly.under_attack(host) {
        return None;                                          // dormant in peacetime
    }
    if cfg.deny_countries.is_empty() { return None; }         // monitoring mode
    let country = self.geoip.country(ip)?;                     // None (private/no db) → skip
    if cfg.deny_countries.iter().any(|c| c.eq_ignore_ascii_case(&country)) {
        Some(format!("geo deny: {country}"))
    } else { None }
}
```

The semantics operators rely on:

- **An empty `deny_countries`** = "monitoring mode": the country lands in the metrics/map, but traffic is never blocked.
- **`attack_mode_only = true`**: the deny list sleeps until the host is marked `anomaly.under_attack(host)`. Useful when you want a dormant geo block that does not punish legitimate traffic from minority countries in peacetime.
- When it fires, the proxy sets `ctx.denied_by = Some("geoip")` on the request and increments `observe_filter_block("geoip")`. Geo deny is one of the cheapest filters (an mmap lookup); it short-circuits early in `request_filter`.

> Domain binding: `geoip_deny` takes a `host`, and `attack_mode_only` is evaluated **per host** via the anomaly detector. The country list itself is nonetheless global (a single `[geoip]` block). For per-domain policies see [26-sites-and-domains.md](26-sites-and-domains.md).

## 7. ASN lookup for reputation

The ASN number of the client IP is used by AS-bound reputation. The binding is implemented by an adapter in `src/geoip.rs`:

```rust
pub struct GeoIpAsnLookup { geoip: Arc<dyn GeoIpLookup> }
impl crate::asn_reputation::AsnLookup for GeoIpAsnLookup {
    fn asn(&self, ip: IpAddr) -> Option<u32> { self.geoip.asn(ip) }
}
```

The adapter exposes the `asn()` method of the already-loaded GeoIP handle as the `AsnLookup` trait, so that the reputation feed uses **the same** database the proxy has already opened (without a second reader). The actual assembly is in `src/bin/aegis-pingora.rs`:

```rust
let asn_lookup: Arc<dyn AsnLookup> =
    Arc::new(GeoIpAsnLookup::new(pipeline.geoip.clone()));
// ... AsnReputation::new(paths, asn_lookup)
```

Behaviour:

- When the ASN database is loaded, AS-bound feed entries (`AS<n>  <score>  <tag>`) match the client's real AS number.
- When the ASN database is **not** loaded, `asn()` returns `None` and **only CIDR entries** from the feed fire (`<cidr>  <score>  <tag>`). The `load_with_asn` log and a comment in `aegis-pingora.rs` warn about this honestly.
- In the data plane the ASN also participates as the `asn_reputation` ML feature (see the `self.geoip.asn(client_ip)` points in `pingora_http.rs`); without an ASN database the feature stays 0.

Details on feeds, scoring and JA4 self-learning are in [12-reputation.md](12-reputation.md); on the ML engine, in [18-ml-risk-engine.md](18-ml-risk-engine.md).

## 8. real_ip — determining the real client IP behind a proxy/CDN

Behind a CDN or a reverse proxy the TCP peer is a rotating edge node, not the client. The real IP is resolved from forwarded headers, **but only when the TCP peer belongs to the trusted set**. This is the input to the whole subsystem: the country and the ASN are computed from the IP the resolver returned, not from the TCP peer.

### The security invariant

The `peer ∈ trusted_proxy_cidrs` check is **unconditional**. If the TCP peer is not trusted, forwarded headers are silently ignored. An attacker who is not sitting behind a trusted proxy cannot spoof their IP by injecting `X-Forwarded-For` or `CF-Connecting-IP`.

### Configuration (both options are **disabled** by default)

| Environment variable | Effect |
|---|---|
| `AEGIS_BEHIND_CLOUDFLARE=1` | trust `CF-Connecting-IP` when the TCP peer is within the built-in list of Cloudflare ranges. Accepts `1`/`true`/`yes`/`on` |
| `AEGIS_TRUSTED_PROXIES=cidr,cidr,...` | additionally trust these CIDRs; consult `X-Forwarded-For` (the "rightmost untrusted" algorithm) |

### The resolution algorithm

The production path is the `resolve_client_ip` method in `src/proxy/pingora_http.rs`:

1. `trusted_proxy_cidrs` is not set → return the TCP peer unchanged (the default behaviour, headers are not read).
2. The TCP peer is **not** in the trusted set → return the TCP peer (the security gate).
3. `AEGIS_BEHIND_CLOUDFLARE=1` → read `CF-Connecting-IP` (the only authoritative value when the terminating edge is Cloudflare).
4. Otherwise → `X-Forwarded-For`, walking right to left, the first IP **not** in the trusted set (the real client immediately before the trust boundary). On any parsing error, or if every hop is trusted, fall back to the TCP peer.

The built-in list of Cloudflare ranges (`CF_IP_RANGES` in `pingora_http.rs`) is active **only** with `AEGIS_BEHIND_CLOUDFLARE=1` and is never consulted by default. CIDR matching uses stdlib bit arithmetic with no external crates; IPv4-in-IPv6 (`::ffff:x.x.x.x`) is not auto-normalised — Pingora's `SocketAddr::as_inet().ip()` already returns a clean `IpAddr::V4` for IPv4 connections.

> Honest caveat about the two implementations. The [`src/real_ip.rs`](../../src/real_ip.rs) module contains a standalone, fully test-covered implementation (`TrustedProxies`, `IpCidr`, `resolve_client_ip`, the `from_config`/`from_env` constructors, reading `AEGIS_BEHIND_CLOUDFLARE`/`AEGIS_TRUSTED_PROXIES`). However, the production pingora data plane does **not** use it, but its own built-in `resolve_client_ip` + `CF_IP_RANGES` + `ip_in_cidr` in `pingora_http.rs` (the `real_ip` module is not referenced anywhere in `src/bin/*` or in the proxy — a `grep` for `real_ip::`/`use crate::real_ip` in the proxy is empty, while `real_ip` is declared in `lib.rs`). The semantics of both implementations coincide (the same security gate, the same rightmost-non-trusted XFF walk, the same priority of CF-Connecting-IP); the difference is only in which code runs on the hot path. The list of Cloudflare ranges is identical in both places and was verified in 2026.

## 9. The world map and Top Countries in the panel

### Recording by country (`observe_country`)

On the ingress of every request the proxy does one lookup and ticks a counter (`src/proxy/pingora_http.rs`):

```rust
if let Some(cc) = self.geoip.country(client_ip) {
    self.metrics.observe_country(&cc, false, false);
}
```

Since the default is `NoopGeoIp` (whose `country()` returns `None` doing no work), this is **almost free** when no database is configured; with a loaded database it is one mmap lookup. The country is also written into the request log row (`EventRow.country`) when the event store is enabled (see [24-request-log.md](24-request-log.md)).

### Cross-worker aggregation (`src/metrics/geo_shard.rs`)

Under `SO_REUSEPORT` each worker keeps its own `by_country` map and sees only its share of the traffic. So that the world map is stable regardless of which worker answered the admin request, a shard+merge-on-read scheme is used (the same pattern as site_map — see [26-sites-and-domains.md](26-sites-and-domains.md) and [06-workers.md](06-workers.md)):

- Each worker takes a slot with a non-blocking advisory `flock` on `.slot-<n>.lock` (up to `MAX_SLOTS = 16`) and periodically writes a snapshot into `shard-<slot>.json`.
- The `CountryRow` row: `country`, `total`, `denied`, `challenged`.
- Reading (`top_countries`) merges **all** shards, summing the counters by country code; shards older than `SHARD_MAX_AGE_SECS = 900` are considered orphaned and skipped (by `written_at_unix_secs` and by the file mtime).
- On a restart the worker re-reads its shard — the counters survive the restart.
- The default directory: `/var/lib/aegis/geo` (overridden by `AEGIS_GEO_DIR`).
- Writes are atomic (a tmp sibling + rename), permissions `0o640`.

### Admin API

| Method + route | Handler | Purpose |
|---|---|---|
| `GET /admin/api/geo/top` | `api_geo_top` | the top 20 countries `[{country, total, denied}]` for the world map and the Top Countries widget; empty if no database is configured (the map renders correctly empty) |
| `GET /admin/api/geoip/status` | `api_geoip_status` | the resolved country database path, `AEGIS_ASN_PATH`, `loaded`, `database_type` + `build_epoch` (from the `.mmdb` metadata), `bundled`, the db-ip attribution |
| `POST /admin/api/geoip/update` | `api_geoip_update` | update the country database to the current month's db-ip Lite |
| `POST /admin/api/geoip/lookup` | `api_geoip_lookup` | **planned**: returns `501` (the GeoIP handle is not yet threaded into `AdminProxy`) |

The full list of admin routes and authentication is in [30-admin-api.md](30-admin-api.md).

### Updating the country database from the panel (`api_geoip_update`)

AEGIS does not pull an HTTP/gzip dependency into Rust, so Update shells out to `curl | gunzip`, atomically replaces the mmdb under `/var/lib/aegis/geoip` and **only on success** writes a restart marker so that the path watcher re-reads the fresh database:

```sh
url="https://download.db-ip.com/free/dbip-country-lite-$(date +%Y-%m).mmdb.gz"
tmp=/var/lib/aegis/geoip/.dbip.new
curl -sfL --max-time 180 "$url" | gunzip > "$tmp"
[ -s "$tmp" ]
mv -f "$tmp" /var/lib/aegis/geoip/dbip-country-lite.mmdb
date +%s > /var/lib/aegis/geoip/.last-update
date +%s > <…/.restart-request>   # restart marker
```

It is launched detached (the download can take seconds); the panel re-polls `status` (the build date changes after the restart). The service restarts itself — no manual `systemctl` is needed. For the restart mechanics see [03-installation.md](03-installation.md).

## 10. Operational cheat sheet

```bash
# Check which database the daemon resolves + its build date
curl -s -H "x-admin-token: $TOKEN" http://127.0.0.1:PORT/admin/api/geoip/status | jq

# Top countries (for the world map)
curl -s -H "x-admin-token: $TOKEN" http://127.0.0.1:PORT/admin/api/geo/top | jq

# Update the country database to the current month (the restart is automatic)
curl -s -X POST -H "x-admin-token: $TOKEN" http://127.0.0.1:PORT/admin/api/geoip/update

# Manual refresh of the ASN database + the reputation feeds (the same script as the timer)
sudo /usr/local/bin/aegis-refresh-feeds

# Set the paths explicitly via env (they beat bundled, and are beaten by [geoip] in the config)
export AEGIS_GEOIP_PATH=/var/lib/aegis/geoip/dbip-country-lite.mmdb
export AEGIS_ASN_PATH=/var/lib/aegis/geoip/dbip-asn-lite.mmdb

# Enable trust in Cloudflare / your own proxies (otherwise forwarded headers are ignored)
export AEGIS_BEHIND_CLOUDFLARE=1
export AEGIS_TRUSTED_PROXIES=10.0.0.0/8,192.0.2.0/24
```

### Typical situations

| Symptom | Cause | What to check |
|---|---|---|
| The world map is empty | the country database is not loaded | `geoip/status` → `loaded`; the presence of `/var/lib/aegis/geoip/dbip-country-lite.mmdb`; press Update |
| Geo deny does not fire | an empty `deny_countries`, or `attack_mode_only` with the host not "under attack", or the country does not resolve | the `[geoip]` block; the host's anomaly status; a private/unallocated IP |
| Reputation only catches CIDRs, not ASes | the ASN database is not loaded | `geoip/status` → `asn_db_path`; run `aegis-refresh-feeds`; the `…only match CIDR entries` log |
| The country/ASN are computed from the edge IP, not the client | real_ip is disabled | `AEGIS_BEHIND_CLOUDFLARE` / `AEGIS_TRUSTED_PROXIES` are set; the TCP peer really is in the trusted set |
| Country counters "jump" between polls | (historically) per-worker maps | it is now aggregated via the geo-shard merge; check that `/var/lib/aegis/geo` (or `AEGIS_GEO_DIR`) is writable |
